# City Map 3D

Выделяешь область на карте → утилита скачивает дороги и воду из OpenStreetMap,
строит рельефную модель (кварталы выше, дороги ниже, вода — углубление), режет её
на куски под стол принтера вдоль рек и крупных улиц, ставит замки «ласточкин хвост»
и сквозные отверстия под светодиоды. На выходе — `city_map.zip` с `piece_XX.stl`
и `layout.svg` (схема сборки 1:1 с номерами кусков).

## Запуск на Mac

1. Нужен Python 3.9+ (лучше 3.11+): `brew install python` или установщик с python.org.
2. Клонируй репозиторий и запусти:
   ```bash
   cd MapCutter
   ./start.command
   ```
   Или двойной клик по `start.command` в Finder (если macOS ругается —
   правый клик → «Открыть»). Первый запуск ставит зависимости в `.venv`, это пара минут.
3. Браузер откроется сам на http://localhost:8000.

На карте:
- **Карта** — двигать и зумить.
- **Область** — тянешь прямоугольник.
- **Светодиоды** — клик ставит точку, клик по точке убирает.
- **Собрать STL** — через 10–60 секунд скачается zip.

Без браузера:
```bash
.venv/bin/python cli.py --bbox 37.60 55.74 37.66 55.765 --width 500 --led 55.75 37.62 -o city.zip
# из скачанного файла:
.venv/bin/python cli.py --bbox 37.60 55.74 37.66 55.765 --osm map.osm -o city.zip
```

## Откуда берутся данные карты

Утилита пробует по очереди:
1. Серверы Overpass: overpass-api.de, maps.mail.ru (VK), overpass.private.coffee, overpass.kumi.systems.
2. Основной API OpenStreetMap (только небольшие области, до ~0.25°²).

Если ничего не отвечает — на странице выбери **файл карты** (или `--osm` в `cli.py`):
- `.osm` — на openstreetmap.org выдели область → «Экспорт» → «Экспорт». Подходит для небольших районов.
- `.osm.pbf` — регион целиком с https://download.geofabrik.de (например, Россия → Центральный ФО)
  или свой прямоугольник с https://slice.openstreetmap.us. Большой регион читается несколько минут.

Большие области (до 2000 км²) скачиваются по частям: Overpass — кусками ~10 км,
кусок, на котором сервер не успел, делится на 4. Основной API OSM — кусками ~2 км,
не больше 100 запросов (это примерно 25 км² в центре города); дальше — только файл.

При мелком масштабе все дороги и реки расширяются до `MIN_ROAD_MM` (0.6 мм), иначе
принтер их не пропечатает, а проезды, дворы и ручьи отбрасываются.

Прямоугольник на карте всё равно нужен: из файла берётся только то, что в него попало.
Если онлайн-загрузка падает, в сообщении об ошибке будет ответ каждого сервера.

## Детализация и скругление

| Уровень | Что остаётся | Упрощение контуров | Скругление углов |
|---|---|---|---|
| **низкая** (по умолчанию) | магистрали, primary–tertiary, реки и каналы | 0.4 мм | 1.5 мм |
| средняя | + жилые улицы | 0.2 мм | 1.0 мм |
| высокая | всё, включая проезды и ручьи | 0.05 мм | 0.5 мм |

Скругляются углы кварталов и четыре внешних угла карты (6 мм, `OUTER_CORNER_MM`).
Стыки между кусками не скругляются — иначе куски не сойдутся.
Радиус можно поменять на странице или `--corner` в `cli.py`; `--detail low|medium|high`.

Куски режутся по крупным улицам и рекам. Если они далеко друг от друга и кусков
выходит много, программа пробует добавить швы по улицам поменьше (tertiary) и берёт
вариант, где кусков меньше.

## Параметры

Константы в начале `core.py`: высоты слоёв (`BASE_H`, `ROAD_H`, `BLOCK_H`),
ширины дорог по классам, размеры замков (`DT_*`), диаметр светодиода (`LED_D`).
Размер стола задаётся на странице (по умолчанию 256 мм). Каждый кусок в STL уже
развёрнут вдоль осей стола и лежит в начале координат.
